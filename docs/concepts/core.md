# Core

Core 不是 agent。它是 Tape 的规则，加上唯一能按规则读写 Tape 的那个循环。

Agent 是一组选择：用哪个模型，说什么提示词，给哪些工具，上下文满了怎么办。改进 harness，就是改变这些选择，再在同一段历史上比较。能比较的前提，是不同的选择读写同一种 Tape、遵守同一套规则。这套所有 harness 共用、任何 harness 都不能违背的规则，就是 Core。

录音机的磁头只把声音写上磁带、把磁带读成声音，不决定录什么、放什么，那是乐手和听众的事。

## 机制，而非策略

Core 只包含机制：无论哪种 agent，要让 Tape 可信都必须成立的东西。策略，即不同 agent 之间各不相同的选择，留在 Core 之外。

| 机制 | 策略 |
|---|---|
| Event 的词汇，Frame 如何回放成上下文 | 系统提示怎么写 |
| 执行工具之前，派发的事实已经落盘 | 装哪些工具，哪些需要审批 |
| 失败也留下记录，再交还宿主 | 用哪个模型，失败后是否重试、换模型 |
| 从读取前缀到调用落带之间，不提交改变上下文的事实 | 何时压缩，摘要怎么写，结果怎么裁剪 |
| 对过去的编辑先经校验，再追加 | 命令、子 agent、动态提示 |

检验方法只有一个：换一种 harness 再走一遍，两者必须能共用同一个 Core，读写同一批 Tape。两者之间不同的部分，都不属于 Core。

## 为什么循环在 Core 里

Head 看起来是 agent 的循环。它在 Core 里，不是因为它是 agent，而是因为 Tape 的规则只有写入方能保证：先落带，再执行工具；失败也要留下记录；每次模型调用的输入，都能从它之前的前缀精确还原。把循环交给宿主，每个宿主都要重新实现这些顺序，Tape 是否可信就取决于宿主写没写对。

Head 自己不做任何选择。模型、工具、系统提示、裁剪与压缩的策略，全部由宿主给出。

## 模型所见，皆在带上

Core 唯一不容例外的规则：模型看到的一切，都从 Tape 回放得出。

改变模型所见的，必须是 Tape 上的一个 Event：系统提示和工具是 Configured，摘要是 Compacted，裁剪是 Pruned。只观察的，读 Head 交出的 Frame 和增量即可，那本身就是按时间排好的事件流，不需要另设钩子。

在调用模型之前悄悄改动消息，看起来方便，代价是 Tape 与模型实际所见从此分叉，那一刻再也回不去。

## 填空，而非挂钩

Core 对外只约定形状：模型提供方如何流式返回，工具如何被调用，Tape 与 Silo 如何存取。宿主填入实现，或者把实现包一层再填入。给工具加审批，就包一层工具，拒绝时抛出异常，结果照常作为出错的工具结果落带；给模型加重试或路由，就包一层提供方。

Core 不提供在运行中途介入的钩子。需要宿主决定的地方，宿主给出的是一条待落带的事实，比如一次裁剪、一次压缩，由 Core 校验后录下。

## 分层

    宿主      组装 agent 的地方
      ↓
    kit       常用的积木：函数工具、技能、读文件
    media     Tape 与 Silo 的实现：内存、文件
    testing   证明实现合格：脚本化的模型，介质一致性检查
      ↓
    core      Tape 的规则与读写它的循环

依赖只朝 Core 一个方向。Core 只依赖标准库、msgspec 和它自身，这条边界由测试守住。kit 不是 agent，它只提供积木，agent 在宿主手里组装成形。

## 什么可以进入 Core

一样新东西想进入 Core，先回答两个问题：

1. 它是否是所有 agent 都必须遵守的？不是，就是策略，留在 Core 之外。
2. 它是否改变模型所见，或者 Tape 的格式？是，就必须是一个 Event，由 Core 定义并校验。

Core 的每一处改动，都会落到每一盘已录的 Tape 和每一个宿主上。所以它保持小，宁可让宿主多写几行，也不替所有 agent 做选择。
